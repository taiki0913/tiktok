# 設計メモ

## 目的
方向性の違う6つのTikTokアカウントを運用し、最終的に **Creator Rewards Program（再生報酬）** で収益化する。

## 全体の流れ
```
[毎朝 6:30]
  競合調査エージェント（企画エージェントのサブエージェント）
    └ YouTubeショート（公式API）・Web検索・Slackで登録された参考TikTok を分析し、「結果だけ」を渡す
  企画エージェント → アカウントごとに3案
        ↓ Slack：オーナーが承認・修正指示・スキップ                     ← フェーズ1（実装済み）
  動画作成エージェント：台本 → 素材生成 → Remotionで編集 → 字幕・音声・BGM  ← フェーズ2
        ↓ Slack：完成動画のプレビュー → 最終OK
  投稿：Upload-Post のAPIで、アカウントの投稿時刻に予約投稿（AI映像はAI生成ラベル付き） ← フェーズ3（実装済み）
        ↓
[翌朝] 投稿した動画の再生数を取得 → 企画エージェントの学習材料に              ← フェーズ3（これから）
```

## 決定事項と理由

| 項目 | 決定 | 理由 |
|---|---|---|
| 収益化 | Creator Rewards Program | 日本も対象。条件は18歳以上・フォロワー1万・直近30日10万再生・**個人アカウント**・**1分以上の動画** |
| 動画の作り方 | 全編AI映像は「都市伝説」の1アカウントだけ。ほかは安価な作り方でアカウントごとに変える | 全編AI映像は報酬の対象外になるリスクと費用が大きい。作り方を変えることで、どれが伸びるかを比べられる |
| 承認 | Slack（企画の承認と、完成動画の最終OKの2回） | ボタン操作がしやすい。AI映像の破綻をそのまま公開しないため |
| 投稿 | TikTok審査を通過済みの投稿代行サービスのAPI | TikTokの開発者ガイドラインでは、自分やチームのアカウント専用の投稿ツールは審査の対象外とされているため |
| 競合調査のデータ | 公式データのみ（YouTube Data API・TikTok oEmbed・自アカウントの成績。Claude のWeb検索は費用の約2/3を占めたため既定で無効） | TikTokのスクレイピングは規約違反。自宅回線から行うと6アカウントにも影響が及ぶおそれがある |
| 実行環境 | オーナーのWindows PC（常駐プロセス＋タスクスケジューラで自動起動） | 追加費用なし。Slack は Socket Mode なので外部公開のURLが不要 |
| 言語 | TypeScript（Node.js） | Claude API・Slack・Remotion（動画編集）を1つの言語で扱える |

## フェーズ2：動画作成（ポリゴン調3D・モーショングラフィックスは実装済み）

### 流れ
1. 企画の決定ボタン → 順番待ちに入る（1本ずつ作る）
2. 台本エージェント（`src/production/scriptAgent.ts`）：場面ごとの読み上げ文・字幕・映像の指示・画面の数字。使った事実をすべて書き出し、自信のないものは Slack で確認してもらう
3. VOICEVOX（`src/production/voicevox.ts`）：場面ごとのナレーション。起動していなければ無音で代用
4. ジョブ（`video/jobs/<日付>-<アカウント>-v<版>/`）：ナレーションの長さから場面の位置を決めた設計図（`job.json`）
5. 動画作成エージェント（`src/production/videoAgent.ts`）：Claude が `Video.tsx` を書き、型チェック → 静止画で見た目を確認 → 直す、をくり返す。読めるのは部品集とお手本だけ、書けるのはジョブのフォルダだけ
6. 書き出し（`src/production/renderer.ts`）→ Slack のスレッドに動画 → 公開OK / 作り直し（映像だけ・台本から）

### 部品集（`video/kit/`）
- 共通の外枠（JobFrame）：字幕・ナレーション・BGM・クレジット・締めの画面。エージェントは映像だけを書く
- 3D：カメラ・光・地面・水面・星空・粒子・家・ビル・江戸の町家・人・木・道路・車・提灯・古墳・山・岩・魚・クラゲ・潜水艇・惑星・恒星
- 画面：大きな数字・チップ・札・板・指し示すラベル・縦の目盛り・棒グラフ・折れ線グラフ
- 説明書 `video/kit/KIT.md` をエージェントに渡している

### 未対応
- 漫画（画像生成AI）・AI映像（動画生成AI）のアカウントは「準備中」と表示して作らない

## （参考）フェーズ2の当初の計画
- 承認された企画から、台本（ナレーション全文・シーンごとの映像指示）を作る
- 作り方ごとの素材生成
  - AI映像：Veo 3.1 / Kling など（Sora 2 APIは2026年9月24日に終了）
  - AI静止画：画像生成API
  - 公開映像：NASA Image and Video Library など
- ナレーション：日本語の音声合成（VOICEVOX、またはクラウドTTS）
- Remotion で、テロップ・字幕・カメラワーク・BGMを付けて縦型動画（1080×1920）に書き出す
- Slack に完成動画を送り、「最終OK」で投稿へ進む

### 見せ方：ポリゴン調3D（試作済み）
参考：「もしもシミュレーション」系アカウントの、ポリゴン調3Dに計器・地図・字幕を重ねた見せ方。
- 作り方：Remotion の上で three.js を動かし、3D空間・カメラの動き・画面の計器・字幕をすべてコードで作る（`video/`）
- 良い点：1本あたりの生成費がほぼ0円／毎回同じ世界観／数字や文字が崩れない／AI生成コンテンツではないので収益化の審査で不利になりにくい
- 試作：「魚が絶対に行けない深さ」冒頭15秒。台本データ（`video/deepsea/timeline.ts`）を変えれば、水深・字幕・目盛りが連動して変わる
- 書き出し時間の実測：15秒の動画で約1分半（GPUなしのクラウド環境・4コア）
- 今後：台本データを動画作成エージェントが毎日書き出す形にし、アカウントごとに3D部品（町・宇宙・海など）を増やしていく
- 注意：参考アカウントの画面デザインはまねず、独自の見た目にする

## フェーズ3：投稿と学習
- 投稿は **Upload-Post**（TikTok の審査済みの投稿サービス）を使う。自作アプリで TikTok の API を使うと、審査を通るまで「自分だけに公開」の投稿しかできないため。
  - Upload-Post の「プロフィール」1つに TikTok アカウント1つをつなぐ。プロフィール名はアカウントID（`history` など）。
  - 公開OKになったら、その日の `postTime` に予約してアップロードする（予約は Upload-Post 側に入るので、投稿時刻に PC が止まっていても投稿される）。投稿時刻を過ぎていたらすぐ投稿する。
  - 二重投稿を防ぐため、アップロードには `<ジョブID>-post<回数>` のキーを付ける（同じキーは24時間以内なら1回にまとめられる）。
  - 5分ごとに投稿の結果を確かめ、投稿・失敗を Slack のスレッドで知らせる。6時間たっても分からなければ「確認できず」にして、自動ではやり直さない。
  - 全編AI映像のアカウントは、TikTok の「AI生成」表示（`is_aigc`）を付ける。
- これから：翌朝、投稿した動画の再生数・いいね数などを取得し、企画エージェントの判断材料に加える（Upload-Post の分析APIを使う予定）

## 未確定・要確認
- Creator Rewards のAI生成コンテンツの扱い：公式規約の原文を、TikTokアプリ内のクリエイターツールで確認する
- TikTokアカウント6つは**個人アカウント**で作る（ビジネスアカウントは報酬の対象外）
- 動画生成AI・画像生成AIの料金は、フェーズ2の実装時に公式の価格表で確認する
